# Нативная защита CAnttRUst в Bearium

Функциональная реализация для Firefox Android 155.0.1, включая одноразовый обход. Сборка APK и отладка на
устройстве отложены по решению владельца; изменения ещё не подтверждены запуском
Gecko/Fenix. Автосборка при обновлении PR отключена.

## Политика и решение пользователя

Точный закреплённый DER Russian Trusted Root CA добавляется только для TLS
серверов. Вместо навязанных Name Constraints нативный CertVerifier проверяет
адрес соединения и SCT до отправки HTTP-запроса. Другие УЦ не затрагиваются.

Отдельный Mozilla MultiLogCTVerifier проверяет подписи SCT из сертификата, TLS
и stapled OCSP. Учитываются ключи, состояние журнала и интервал окончания срока
сертификата. Требуется Yandex; усиленный режим дополнительно требует второго
независимого оператора. Российские журналы не добавляются в общий список Mozilla.

При отказе этой дополнительной политики, включая HSTS, сама страница ошибки
показывает причину, домен и кнопки «Назад», «Продолжить один раз» и
«Разрешить этот домен», как предупреждение расширения CAnttRUst. Исключение отменяет только проверку зоны,
только SCT либо обе. Самостоятельные ошибки имени, подписи, срока, EKU и отзыва
сертификата остаются в ведении штатной проверки Firefox.

Исключения действуют для точного хоста без автоматического охвата поддоменов:

- до закрытия браузера — память, default-ветка preferences;
- один час — абсолютное время окончания, в обычном режиме переживает перезапуск;
- постоянно — user-ветка preferences;
- приватно — отдельная память до закрытия всех приватных вкладок.

### Одноразовый переход

Кнопка «Открыть эту страницу один раз» выдаёт разрешение только одному
верхнеуровневому HTTPS-запросу в исходной вкладке. Сопоставляются полный сетевой
URL (включая путь и query, без fragment), хост и приватный режим. Неиспользованный
допуск истекает через 60 секунд; закрытие вкладки, отмена и другая навигация его
удаляют. Разрешение расходуется до выбора соединения. Вложенные ресурсы,
повторный запрос и редирект его не наследуют. В preferences ничего не записывается.

Реализация использует отдельный parent-only метод HTTP-канала. Контентный процесс
не может установить флаг через tlsFlags или перенести его через redirect IPC.
Для этого единственного перехода выбирается свежее HTTP/1-соединение без keep-alive,
HTTP/2/3, Alt-Svc и записи HTTP-кэша. Нативный флаг доходит до CertVerifier через
существующий IPC флагов проверки. Проверка сертификата HTTPS-прокси исключением
сайта не ослабляется. В отчёте явно отмечается одноразовый обход.

Время окончания проверяется в нативном verifier при каждом handshake. Фоновый
таймер удаляет просроченные разрешения и закрывает соединения; пробуждение
устройства также запускает очистку. Изменение настроек пересоздаёт CertVerifier,
сбрасывает TLS-сессии и закрывает активные сетевые соединения.

Для цепочек с этим корнем CommonSocketControl запрещает объединение разных
хостов; SSLTokensCache не возвращает токены таких цепочек, включая ранее
сохранённые. Это предотвращает обход новой проверки через resumption и 0-RTT.

## Интерфейс

«Щит» и предупреждение показывают число заблокированных запросов и доменов.
Текст содержит полный счётчик запросов; компактный badge ограничен `99+`.
Недоступная проверка отмечается `?`; успешный SCT основного документа — `CT`.
Внутренняя страница `about:rufox-protection` предоставляет:

- список наблюдавшихся доменов через этот УЦ, индивидуальные галочки и выбор всех
  заблокированных доменов;
- массовое разрешение с областью и сроком, ручное добавление и удаление;
- возврат на исходный сайт одним переходом после массового разрешения;
- причины отказа зоны и SCT, действующие исключения, число операторов;
- для SCT — журнал, источник, время, результат проверки срока/состояния;
- количество неизвестных журналов, ошибок формата, подписи и времени;
- переключатель усиленного режима и состав встроенного списка журналов.

Страница привилегированная и не MAKE_LINKABLE. Изменения требуют доверенного
действия пользователя. Внешние значения выводятся через textContent; CSP
запрещает внешние ресурсы. Программный клик не создаёт исключение.

## Данные и границы диагностики

Предупреждение выбирает родительский LoadURIDelegate по нативному отчёту
основного канала и URL текущей вкладки. Отчёт собирается в OnStartRequest до
вызова обработчика ошибки, включая отказ TLS. Привязка использует
`targetBrowsingContextID`; загрузка внутренней ошибки сохраняет счётчики.
Параметры предупреждения читаются из documentURI: адресная строка страницы
ошибки сохраняет URL сайта. Другие ошибки используют штатную страницу Fenix.

JSON результата передаётся вместе с TransportSecurityInfo: поток проверки → IPC
socket process → socket control → HTTP channel. Это результат конкретной TLS
проверки, а не предположение по имени хоста или коду общей ошибки TLS. Поле
сериализуется и в HTTP-кэш вместе с остальными сведениями о TLS (формат 10),
поэтому результат закэшированного ответа относится к исходному соединению.

GeckoView связывает каналы с вкладкой и поколением навигации. Поздний ответ
предыдущей страницы не пополняет новую. Сведения удаляются при закрытии вкладки;
список вкладки и счётчики не сохраняются отдельно на диск. Учитываются только
наблюдавшиеся каналы с нативным отчётом. Запросы без привязки к вкладке и ответы
без сетевого канала не означают успешную проверку и не выдумываются в списке.

Список ограничен 1000 доменами, подробности — 20 последними разновидностями
отчётов. Счётчики продолжают учитывать наблюдавшиеся запросы сверх лимитов.
При сокращении списка число доменов показано как нижняя граница («не менее»).
В отчёте показываются максимум 128 проверенных SCT; политика учитывает все SCT.

## Проверки после завершения реализации

Локальный набор: 44 теста. Исполняется настоящий JS страницы, сборщика и
преобразованного обработчика ошибок GeckoView с подменой сервисов; C++-тесты
проверяют правила доменов/сроков и контракт API одноразового разрешения.
Добавлены проверки отказа TLS до показа ошибки, целевой вкладки, сохранения
счётчиков, повторного перехода, отсутствия двойного подсчёта и прямых кнопок.
Преобразования применены повторно к доступным исходникам Firefox 155.0.1.
Полная сборка Gecko/Fenix и работа этой версии интерфейса на устройстве
этими проверками не подтверждаются; APK автоматически не собирался.

Перед выпуском проверить:

1. Компиляцию Gecko/Fenix, API compatibility и применение overlay к stable.
2. Одноразовый переход через реальный TLS, отсутствие переноса на redirect,
   subresource, другую вкладку и HTTPS-прокси; отсутствие reuse и HTTP-кэша.
3. Успех/отказ SCT из всех трёх источников, режим двух операторов и причины ошибок.
4. Переход через исключение зоны/SCT/обоих, HSTS, массовое разрешение и один reload.
5. Истечение часа, перезапуск, выход из private mode, закрытие вкладок и resume.
6. Корректность IPC отчёта при успехе и ошибке; старый/новый HTTP-кэш.
7. Параллельные вкладки, редиректы, поздние ответы, iframe, fetch и очистку счётчика.
8. HTTP/2, HTTP/3, запрет coalescing/resumption/0-RTT и смену политики во время handshake.
9. Сохранение штатных отказов PKI при любом пользовательском исключении.

## Источник политики

Список журналов из CAnttRUst: версия 1.229, 2026-08-12. Обновляется с браузером,
без удалённого исполняемого кода. Криптография реализована средствами Mozilla;
TypeScript расширения в APK не включён. SCT — обещание журнала, не inclusion
proof и не подтверждение отсутствия перехвата.
