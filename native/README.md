# Нативная защита CAnttRUst в Rufox

Рабочая ветка интеграции для Firefox Android 155.0.1. Не выпускать до сборки
Gecko/Fenix и проверки TLS на устройстве.

Обязательное свойство: пользователь может разрешить любой отказ дополнительной
политики Минцифры. Такое разрешение не отменяет самостоятельные ошибки имени,
срока действия, подписи и отзыва сертификата.

Проверка выполняется средствами Gecko до HTTP-запроса. Российские CT-журналы
используются только для отслеживаемого УЦ и не добавляются в общий список Mozilla.

## Что реализовано

- Вместо добавленных Name Constraints проверяется точный адрес запроса.
- SCT проверяет отдельный MultiLogCTVerifier; учитываются ключ, состояние
  журнала и интервал окончания срока сертификата. По умолчанию требуется Yandex.
- `security.rufox.exceptions`: список точных имён с областью `zone`, `ct`, `all`.
  Исключение не вызывает стандартный механизм отключения проверки TLS.
- `about:rufox-protection` управляет исключениями. Страница привилегированная,
  не MAKE_LINKABLE; изменения требуют доверенного пользовательского клика.
  Внешние значения выводятся через textContent; CSP запрещает внешние ресурсы.
- Приватные исключения находятся в default-ветке prefs (без записи в prefs.js)
  и очищаются после закрытия всех приватных контекстов.
- При изменении политики пересоздаётся CertVerifier, очищается TLS-кэш,
  страница управления закрывает активные соединения.
- Для цепочек с этим корнем CommonSocketControl запрещает объединять разные
  имена; SSLTokensCache не возвращает токены таких цепочек, включая сохранённые
  предыдущей версией. Эти изменения не отключают HTTP/2 и HTTP/3 для других УЦ.
- Панель «щита» открывает управление. На странице ошибки TLS есть отдельный
  переход; он применим и к HSTS, но не отменяет самостоятельные ошибки TLS.

## Проверки до выпуска

Локально проверены 39 тестов, включая работу настоящего JS страницы с заменой
browser services: множественное добавление, удаление, запрет программного клика,
недопустимый URL и изоляция приватных разрешений. Проверены однозначность и
повторное применение новых патчей на исходниках FIREFOX-ANDROID_155_0_1_RELEASE.

CI PR собирает Gecko/Fenix для трёх ABI и сохраняет APK в artifacts. Публикация
GitHub Release разрешена только из main и никогда из pull_request.

До слияния нужны успешная компиляция и проверка на Android:

1. Обычный HTTPS и сайт с отслеживаемым УЦ и подходящим SCT открываются.
2. Отказ зоны и отказ SCT обходятся со страницы ошибки и через «щит».
3. То же для HSTS; разрешение `zone` не отключает CT и наоборот.
4. Сервер не получает HTTP-запрос до разрешения; ошибочные подпись, имя, срок
   сертификата не обходятся разрешением нашей политики.
5. HTTP/2, HTTP/3, возобновление TLS, 0-RTT, повторная навигация, фоновые запросы.
6. Удаление разрешения при уже открытом соединении и параллельном handshake.
7. Закрытие приватных вкладок и перезапуск не сохраняют приватные разрешения.

Счётчик запросов по вкладкам, список обнаруженных доменов с галочками и
диагностика конкретного SCT в панели пока не реализованы. Сейчас несколько
доменов вводятся текстом, а стандартная ошибка TLS даёт ссылку на управление
без утверждения, что любой отказ TLS обязательно связан с Минцифры.

## Источник политики

Данные журналов: [CAnttRUst](https://github.com/ISAIandCO/CAnttRUst/blob/main/src/policy/ct/yandex-nuc-log-list.json),
версия списка 1.229, дата 2026-08-12. Алгоритм нативной реализации использует
криптографические функции Mozilla; TypeScript-код расширения не включён в APK.
SCT — обещание журнала, а не доказательство отсутствия MitM и не inclusion proof.
